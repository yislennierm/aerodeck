AERODECK WORKFLOW / INFORMATION ARCHITECTURE AUDIT
Revision ICON-NAV-20261016; canonical source reviewed read only; 2026-10-16.

The user's criticism is supported by the implementation. The redesign improved icon consistency but retained several competing navigation systems and did not provide a complete radio-button workflow. Passing the earlier touch-routing tests did not establish intuitive operation or hardware parity. The most consequential problems are behavior, not ornament: physical input cannot open the drawer, settings cannot be committed without touch, RTN exits an edit, GPS home/track processing depends on the displayed page, and tapping the selected Flight reloads its graphics.

QUANTITATIVE MAP
There are12 screens in6 sections, exposed through5 global navigation surfaces:
1. Six section icons, each remembering a subpage.
2. Current-section context tabs.
3. A flat12-icon drawer.
4. A different-looking linear12-page PAGE cycle.
5. Four footer shortcuts; a warning replaces all four with one alert destination.
There are also3 local navigation families: Setup list/row paging; Stick/Sensor/arming-detail paging; and cross-links between GPS/VTX/setup pages.

Top bar34 + context26 + footer26 reserve86/272 vertical pixels (31.6%). The main common content region is180px high. This reservation is not itself a bug, but adding legacy per-page headers beneath it wastes render work and hides page state.

The section order is Flight(1,10), Data(5,3,9), GPS(7,2), VTX(11), Setup(8), Tools(6,4,12).
The drawer/PAGE order is1,5,2,7,3,9,10,6,8,4,11,12.
These orders do not form the same spatial sequence, so a user cannot transfer the grouped visual map to the physical PAGE cycle.

Toolbox declares8 modules: Dashboard, Configuration, Telemetry, VTX, GPS, Arm Stops, Sticks, About. The common bar exposes up to7 because Dashboard is the return destination, and capabilities filter that same list. This does not mean Toolbox has no complexity or that every icon is self-evident; its smaller advantage is one consistent module model with page-local hardware interactions. Original bytecode verifies the menu/config/stick control claims below.

PRIORITIZED FINDINGS

WF01 [HIGH] Hardware navigation cannot open the all-screens drawer
Impact: Rotary selection only works after touching the grid. A user navigating with the radio buttons must remember a twelve-page cycle; SYS/MENU does not expose the menu.
Smallest remedy: Map one documented physical action to focus/open the existing drawer, with ENTER to select and RTN to cancel. Keep touch behavior.

Verification: Canonical app boundary probe: event42 representing SYS did not open the drawer. Static run() has no SYS/MENU/long-ENTER branch. Original Toolbox MENU bytecode confirms SY, EN, EX, RT/LT controls.

WF02 [HIGH] Settings can be edited by rotary but cannot be saved or moved between lists without touch
Impact: PAGE from Setup leaves for Sensors instead of selecting the next settings list. ENTER only toggles edit mode; neither SAVE nor REVERT is focusable. The hardware workflow reaches a dead end after adjustment.
Smallest remedy: Make local settings interaction own PAGE while in Setup, and expose Save/Revert through the same focus model or explicit physical commit/cancel actions.

WF03 [HIGH] RTN exits the full app while editing instead of backing out
Impact: A familiar cancel/back action destroys the current editing session on reopen. Ordinary pages also have no physical 'back to Flight'; users must traverse the global cycle.
Smallest remedy: Prioritize cancel-edit, close-local-view and return-to-Flight before full app exit. Keep a deliberate app-exit action distinct and do not silently commit.

WF04 [HIGH] Auto-home and track recording depend on looking at a GPS page
Impact: Starting on Flight with valid GPS and auto-home enabled leaves HOME blank. The track is not a record of the flight; it records only time spent on GPS Details/Track screens.
Smallest remedy: Update navigation state from the existing sampled data once per foreground frame, independently of which page renders. Keep rendering read-only and do not add duplicate sensor reads.

WF05 [MEDIUM] Tapping the already-selected page reloads its graphics
Impact: A harmless tap on the current icon/context/footer causes full garbage collection and reloads Flight chrome, bezel and digit glyphs. It can visibly stutter without changing page.
Smallest remedy: Close the drawer if needed, but return early from a same-page selection unless the user explicitly requested a refresh. Preserve the current graphics cache.

WF06 [MEDIUM] The new shell is composed over legacy page headers
Impact: Pages draw titles, telemetry badges, model/source counts and navigation summaries that are then completely covered by the shell. Important page-specific information vanishes, and the code retains competing layouts rather than one layout owner.
Smallest remedy: Give the shell sole ownership of the header/context/footer and remove legacy drawing there. Place any still-needed page status once in the reserved body or shared status region.

- Edit and save battery cell count by one: touch 6; hardware incomplete. Can open Setup in4 PAGE presses, but list selection and Save need touch.
- Read the second Stick Guide page: touch 2; hardware incomplete. PAGE opens a different screen and rotary NEXT has no guide handler.
- Change one saved VTX frequency by1MHz: touch 5; hardware incomplete. No physical commit/list access; opening favourites is a touch action.

RECOMMENDED SMALLEST SEQUENCE
1. Complete the physical menu/edit/cancel contract before changing appearance again.
2. Move home/track state updates out of renderers; keep one shared telemetry sample.
3. Stop same-page resource reloads and remove page headers overwritten by the shell.
4. Reduce duplicate navigation or align its orders; retain the icon-only top bar requested by the user while giving unfamiliar drawer icons a learnable preview.
5. Make local capability labels, Save scope and inert/reference controls explicit.
6. Then verify native screenshots under long/missing/warning values and compare physical-radio responsiveness with identical radio/quad/RF state.

The current audit does not recommend another wholesale visual restart. It identifies specific workflow and composition faults that can be corrected while retaining the cockpit texture, circular attitude instrument and the new icon family.
