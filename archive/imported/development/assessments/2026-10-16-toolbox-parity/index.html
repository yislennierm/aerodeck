AERODECK has a stronger visual direction than its interaction model. It is not yet a Toolbox feature replacement. The current complexity comes from layering navigation and reference screens over incomplete workflows, not from needing more decoration. Why it feels more complicated than Toolbox

There are five global navigation surfaces for twelve screens, with different groupings and behaviors. The most serious gaps are physical-input dead ends, inconsistent Back/Save behavior and page-dependent state processing. These are source and routing observations, not results from a timed usability study.

Hardware navigation cannot open the all-screens drawer

Rotary selection only works after touching the grid. A user navigating with the radio buttons must remember a twelve-page cycle; SYS/MENU does not expose the menu.

Smallest remedy: Map one documented physical action to focus/open the existing drawer, with ENTER to select and RTN to cancel. Keep touch behavior.

Verification and evidence

Canonical app boundary probe: event42 representing SYS did not open the drawer. Static run() has no SYS/MENU/long-ENTER branch. Original Toolbox MENU bytecode confirms SY, EN, EX, RT/LT controls.

This is a navigation proposal, not an implemented reskin. It keeps the approved cockpit and icon family. Six direct destinations use one order for touch and PAGE; local views and tools sit beneath their owner. The current page name and focus feedback explain icon meaning without adding paired labels everywhere. If Video has no connected backend, its status must say so.

Design principles and limits

Stable ordering and sensible focus are supported by W3C consistent-navigation guidance and focus-order guidance. These are applied as design principles, not a radio compliance claim. Apple’s tab-bar guidance favors labels; the requested icon-only main bar is a deliberate constraint, so it needs a readable current-page title and discoverable focus/learning behavior. Original icon-comprehension research supports testing recognition rather than assuming custom drawings are universally understood.

Success means common tasks work with both touch and the radio’s controls, values agree across views, source age and action scope are clear, and the accepted native cockpit remains intact. A prettier screenshot alone does not establish those outcomes.
