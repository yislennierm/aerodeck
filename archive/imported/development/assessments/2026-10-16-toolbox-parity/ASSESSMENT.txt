AERODECK vs TOOLBOX2 — 1:1 FEATURE AND UI ASSESSMENT
16 October2026 · ICON-NAV-20261016

AERODECK has a stronger visual direction than its interaction model. It is not yet a Toolbox feature replacement. The current complexity comes from layering navigation and reference screens over incomplete workflows, not from needing more decoration. Preserve the accepted cockpit and icon family; fix the interaction contract and shared state before adding another skin.

This audit inspects installed build ICON-NAV-20261016 (SHA256 f4d5d17879f7aae8858f11f9ec09d631ad524b1326e8ff95772a79d42526bdd8) and the supplied fm2m-toolbox-200-edgetx Toolbox2.0 reference. It does not claim coverage of an uninspected newer Toolbox edition. Original bytecode was checked where recovered Lua has damaged control flow. Native pictures use the exact app source plus isolated synthetic inputs, all29 arming-disable flags and one custom5000MHz favourite. Runtime is TX16S EdgeTX3.0.0 WASM; the physical radio has2.12.4. Font measurements and clipping are native-preview evidence, not new radio screenshots. Hardware latency, outdoor legibility, finger accuracy and sustained live attitude performance were not measured. App/widget/assets on the radio were not changed.

READ THIS FIRST
Native flight display: Working render/data paths; sustained physical response not measured by this audit.
Telemetry: Current27-field table; Min/Max, complete browsing and consistent Inspector/widget sources still incomplete.
Battery/session: Basic pack readings and warnings work; radio battery, real timers, five presets and quick pack/mute/new-flight actions are missing or partial.
GPS/home: Current details and local plot work; home capture and track sampling run only on GPS pages, source changes do not clear history, real fix/quality/satellite metadata absent.
FC/arming: Bounded read-only identity/status and real disable explanations work; no general FC editor is implied by Toolbox settings.
VTX: Eight local frequency notes; device state/tables/PIT/power/apply/save are not implemented.
Configuration: All12 headings mapped explicitly below. Similar list counts conceal different settings, placeholders and inconsistent enable/save semantics.

The report contains44 core checks,12 explicit configuration-category mappings plus33 deeper settings/transport checks,14 workflow findings and12 task routes. These tables overlap; do not sum their status counts or publish a completion percentage. Working means an executable path with a runtime consumer, not full end-to-end certification. Compact-widget extras and other transport/FC extensions are not blockers for the selected TX16S/Betaflight/ELRS scope.

CONFIRMED VISUAL / COMPOSITION FINDINGS

VIS01 [MEDIUM] Custom VTX card label is overwritten
In the native custom-frequency fixture, CUSTOM measures98px at x15. Its card spans x8–82; the next card starts x87 and paints over the text. This is reproduced clipping, not a general impression.
Remedy: Use the frequency as the primary label when no standard channel exists; fit or wrap secondary text to a measured content box.
Evidence: telem.lua1044–1059; screens/audit-video-custom.png; native lcd.sizeText measurement.

VIS02 [LOW] Arming title has no right gutter
Accelerometer not calibrated measures313px at x159, ending at x472, the panel edge. It fits in the inspected native runtime; it is not proven clipped.
Remedy: Reserve an8px inner gutter and wrap the title by measured width, rather than shrinking every title.
Evidence: telem.lua1017–1020; screens/audit-arm-24.png.

VIS03 [MEDIUM] Read-only setup lists still offer editing actions
VTX category8 contains four informational rows, including NOT IMPLEMENTED, but uses selection/edit styling and presents minus, plus, Save and Revert. Application category12 is mostly notes but its MSP control really works.
Remedy: Render notes as status/help. Offer edit/commit controls only for editable items and show their scope. Do not remove the working MSP Off action.
Evidence: telem.lua198,203–204,311–341; screens/audit-config-08.png.

VIS04 [MEDIUM] Shell and page renderers both own the same header space
Legacy page headers/status are drawn before the shell covers them. Examples include Sensor Inspector source count and prior live-data badges. This is actual render composition overlap, even where the final screenshot looks tidy.
Remedy: Let the shell own header/footer rectangles; render each needed status exactly once in an assigned body region.
Evidence: telem.lua669–671,771–777,865–872,1111–1165,1224–1227; WF06.

VIS05 [LOW] Graphs show samples without usable scales
Power and RC Link traces show a sample count but no time axis, numerical scale or min/max. Voltage uses a zero-based pack-dependent range and current a fixed0–100A range, so small changes can look flat.
Remedy: Show units, latest/min/max and a defined time window; use stable bounded scales with gaps for missing data.
Evidence: telem.lua931–968; screens/audit-power.png; screens/audit-link.png.

VIS06 [MEDIUM] Technical values change meaning across views
Telemetry converts attitude to degrees; Sensor Inspector displays raw0.19/0.49 radians without units. RFMD3 and DOWN99% are not explained. GPS Details accurately refuses to invent a fix, but the long unavailable message occupies the small satellite summary.
Remedy: Use shared value formatting and source identity, decode RF captions only with known protocol/version, and place compact unavailable labels with detail on selection.
Evidence: telem.lua404–429,655–689,959–968; CORE12/13/32; screens/audit-sensors.png.

VIS07 [MEDIUM] Fixed metadata is styled as a command
Track NORTH UP is drawn like adjacent enabled buttons, but no handler covers it. The LIVE SENSORS button refreshes binding metadata and has no confirmation; it does not change live/demo mode.
Remedy: Draw North up as plot metadata. Name refresh by what it does and acknowledge completion.
Evidence: telem.lua536–540,604–606,1207–1209; screens/audit-track.png.

VIS08 [MEDIUM] Space is allocated to repeated status and navigation
Top bar34px + context26px + footer26px =86/272px (31.6%). The shared main content is180px high. Flight repeats link and pack readings in sidebars/footer. The size alone is not a defect; redundant content must earn its space.
Remedy: Preserve cockpit geometry initially. Remove redundant navigation before shrinking targets or instrument art; reuse a single stable status/alert presentation.
Evidence: telem.lua1085–1165; workflow information_architecture; screens/audit-flight.png.

SCREEN-BY-SCREEN VERDICT
Flight: Keep the original chrome, instrument scale and unavailable state. Remove repeated navigation/status and active-page reloads.
Telemetry: Dense but readable for sample values. Fixed27 slots; no Min/Max or full browsing. Test wide signed values and use shared formatting.
Power: Good basic hierarchy. Add chart units/scales/time and a direct pack workflow; current footer repeats pack voltage.
RC Link: Values fit. Decode raw RFMD/DOWN, label direction and units, and make trace scale/time useful.
GPS Details: Coordinates fit. Satellite count is not a fix; retain honest missing metadata. Continuous home acquisition is a backend defect.
Track / Home: Useful local plot. NORTH UP is inert; refresh is ambiguously named. Keep local-home provenance and add age/time.
Arm Stops: Readable split layout; longest known title has zero gutter. Measure/wrap title width. Empty space is acceptable.
Video: Confirmed CUSTOM clipping. This is an offline reference page, not connected VTX control; the dominant attitude inset does not close that gap.
Setup: A changing list carousel, a rows pager, edit mode and two save stores are too many rules. Use category selection and one clear transaction model.
Stick Guide: Diagrams and labels fit. Paging is touch-only, both arrows toggle, page position missing. It is a reference, not transmitted commands.
Sensor Inspector: Fits but lacks units and visible page position. Header source count is covered, refresh and next are conflated, source lookup is unqualified.
Diagnostics: Useful build/connection detail. Treat as a status destination; displayed audit FPS includes instrumentation overhead and is not a benchmark.

RECOMMENDED DELIVERY ORDER

1 · Repair the interaction contract
Make menu/category/action/save/cancel reachable by hardware; make RTN back/cancel; ignore same-page navigation; remove overwritten header draws; fix measured VTX text bounds and inert button styling. Keep the existing cockpit and MSP loop.
Gate: edit/save/revert/cancel entirely with physical controls and touch; no active-page bitmap reopen; long/reference/error screens fit.

2 · Consolidate navigation and settings
Six stable destinations in the same touch/PAGE order. Replace the duplicate12-tile chooser with useful quick actions. Put Power/Link in Telemetry detail, arm/connection/sensors in Status, reference tools in Setup. Use a settings category list instead of dynamic ordinal arrows.
Gate: a new user finds each task without learning a second navigation map; no hidden Save scope or control that changes meaning without feedback.

3 · Correct continuous state and source consistency
Move home/history updates out of renderers, cap buffers after setting changes, invalidate source-dependent history deliberately, share qualified source binding and units across app/widget/inspector. Define Auto/Off with a safe legacy migration.
Gate: home/track keep updating on Flight, mapping changes never retain an unrelated home, and all views agree on values and freshness.

4 · Close common flight-workflow gaps
Radio battery, read real Timer1–3, quick pack/new-flight/mute/reload, five useful presets, Current/Min/Max. Keep measured cells distinct from computed average.
Gate: pack/session changes have explicit reset scopes; native timer and sensor extrema agree with EdgeTX; missing sensors stay unavailable.

5 · Complete connected VTX and richer GPS
Add bounded typed read jobs and device identity, VTX status/tables and measured GPS fix metadata. Only then add explicit VTX apply/readback and separate persistence. Retain existing status cadence and arm/link stop gates.
Gate: values match the FC; custom/partial/stale tables are honest, reads do not starve status, writes distinguish requested/reported/saved and cancel appropriately.

UX GUIDANCE AND INTERPRETATION
Stable ordering and predictable operations are design recommendations backed by the source findings and consistent-navigation/focus guidance. W3C web criteria are cited as principles, not a certification claim for this radio. Apple recommends labels for tab icons; this design deliberately retains the user-requested icon-only main bar, with a readable current-page title and hardware-focus names. Original icon-comprehension research supports validating the custom symbols with users rather than assuming recognition. No requirement to restore paired labels everywhere is inferred.

AERODECK WORKFLOW / INFORMATION ARCHITECTURE AUDIT
Revision ICON-NAV-20261016; canonical source reviewed read only; 2026-10-16.

The user's criticism is supported by the implementation. The redesign improved icon consistency but retained several competing navigation systems and did not provide a complete radio-button workflow. Passing the earlier touch-routing tests did not establish intuitive operation or hardware parity. The most consequential problems are behavior, not ornament: physical input cannot open the drawer, settings cannot be committed without touch, RTN exits an edit, GPS home/track processing depends on the displayed page, and tapping the selected Flight reloads its graphics.

QUANTITATIVE MAP
There are12 screens in6 sections, exposed through5 global navigation surfaces:
1. Six section icons, each remembering a subpage.
2. Current-section context tabs.
3. A flat12-icon drawer.
4. A different-looking linear12-page PAGE cycle.
5. Four footer shortcuts; a warning replaces all four with one alert destination.
There are also3 local navigation families: Setup list/row paging; Stick/Sensor/arming-detail paging; and cross-links between GPS/VTX/setup pages.

Top bar34 + context26 + footer26 reserve86/272 vertical pixels (31.6%). The main common content region is180px high. This reservation is not itself a bug, but adding legacy per-page headers beneath it wastes render work and hides page state.

The section order is Flight(1,10), Data(5,3,9), GPS(7,2), VTX(11), Setup(8), Tools(6,4,12).
The drawer/PAGE order is1,5,2,7,3,9,10,6,8,4,11,12.
These orders do not form the same spatial sequence, so a user cannot transfer the grouped visual map to the physical PAGE cycle.

Toolbox declares8 modules: Dashboard, Configuration, Telemetry, VTX, GPS, Arm Stops, Sticks, About. The common bar exposes up to7 because Dashboard is the return destination, and capabilities filter that same list. This does not mean Toolbox has no complexity or that every icon is self-evident; its smaller advantage is one consistent module model with page-local hardware interactions. Original bytecode verifies the menu/config/stick control claims below.
