REFERENCE CORRECTIONS
- Original Toolbox CRSF GPS code infers POS_FIX from a satellite threshold and
  derives its GPS_HDOP value from Sats-4. That is not measured HDOP or a verified
  3D fix. We should improve this, not copy the badge. MSP106 supplies a fix
  boolean and PDOP (where supported), not precise fix type or measured HDOP.
- Toolbox's Flight Controller settings are MSP connection/polling preferences,
  not a full PID/rate/motor configurator. Do not promise one from those headings.
- Original VTX control has explicit send/read branches. Recovered Lua lost the
  branch and fields. All implementation must follow original bytecode plus
  official Betaflight formats, not execute the damaged recovery.
- Toolbox widget background continuation is not proved by a callback alone;
  AERODECK currently has no hidden alerts/MSP/session recording. State this scope.

ORDER OF DELIVERY — each row has its own completion gate

   distinguish draw cadence from sensor updates and compare known physical poses.

   I adds a visible build ID; it does not close the physical-performance gate.

   Gate: tool, compact widget and full-screen agree, even with renamed/colliding

2. Complete pack/session workflows (P1, medium UI/state work).
   Fast pack selector, chemistry/cells/capacity, new-flight/reset scope, mute,

   Gate: swap/reuse packs without silently carrying wrong consumption/home/timer;
   settings survive, cancellation has no partial changes, histories stay bounded.
3. Deliver real connected read-only pages (P1, larger transport work).

HOW TO IMPROVE THE UI OVER TOOLBOX — proposed acceptance, not a completed claim
- Fewer navigation label pairs, distinctive native symbols, stable positions,
  full-cell touch targets, active backplate plus marker, and physical-key routes.
  The focused drawer caption/page title supplies orientation. Icon comprehension
  still needs user evaluation: these custom symbols are not universally known.
- Every value has current/historical/missing semantics; real fix/PDOP must replace
  inferred quality labels. Keep local-home and FC-home provenance explicit.
- Every command distinguishes pending, accepted, readback-confirmed and saved;
  no fake Apply, no silent EEPROM save or blind retry of an ambiguous write.
- Make common pack/mute/new-flight actions reachable from the cockpit with fewer
  steps than general configuration. Record actual steps and failed selections.
- Compare native 480x272 views, outdoor legibility, finger targets, rotary paths,
  and several minutes of real-data use with Toolbox under the same conditions.
  Release requires no ongoing slowdown, memory growth or state loss. Native WASM
  checks prove layout/routing; they cannot establish superiority on the radio.

  VTXMSP-disassembly.txt — original send/read gates and write/save/readback
  MSPC0089-disassembly.txt — real factory-byte consumption absent in decompile
  GPS-TBS-disassembly.txt — actual inferred fix, quality score, local-home lock

1. SHARED TRANSPORT FOUNDATION — dependency for all new MSP features
Toolbox original MAIN/ML source178-196 gates MSP on enabled+telemetry+disarmed,
resets the deadline when blocked, and waits1s before requests. It runs protocol
work before sensor reads. Original MSPINIT source106-109 sets five attempts,
CRSF response wait5s, start delay1s; MSPML114-120 clears/reset the timed-out
exchange and drops the queue head after attempt limit. Read/write jobs share
one queue. Do not reproduce its unbounded clearBuffer loops in our UI callback.

AERODECK already bounds one outstanding request,4pops/callback,256payload bytes,
5s reply wait and busy/error backoff. Extend this with typed jobs, not arbitrary
MSP execution: command, params, read/write kind, expected reply shape, deadline,
retry budget, feature owner and target FC identity. Parameterized read jobs are
required for137/138. Correlate their echoed index as well as command ID, because
a late137 reply for the previous band must not populate the current band.
Keep one CRSF consumer/dispatcher and one fresh-data snapshot for the UI.

CRSF read request type0x7A, write0x7C, reply0x7B. Existing addresses are request
C8,EA and responseEA,C8. Retain MSPv2 sequence/header validation and outer CRSF
CRC boundary. Do not add a serial MSP CRC inside the CRSF body. Keep generic
unsupported-command errors separate from no link and malformed replies.

Acceptance: successful delayed/chunked replies; wrong echoed index, interleaved
late replies, timeout, busy TX, reconnect, model change and armed/stale-FM stop
cases all preserve bounded work and never commit another FC's cached settings.
Attitude cadence must be checked on the actual radio alongside Toolbox before
claiming the reported slowdown is resolved. The ELRS temporary reply boost from
MSP explains a concrete difference; identical saved RF settings are not proof
of identical active link behavior. Keep the current3s status job from starving
behind table reads. No guaranteed in-flight boost: this path stops when armed.

2. LIVE VTX STATUS + ACTUAL FC TABLES — highest missing user-facing capability
Toolbox supports FC MSP and a separate direct TBS RX path. Implement FC MSP
first, because this is the user's Betaflight/CRSF setup; direct TBS RX is not a
necessary dependency for that path. Current favourite selection is only local.

Read88 MSP_VTX_CONFIG, empty request. For verified API1.46/1.47 full response:
 byte1 device/protocol type;2band;3channel;4power index;5PIT status;
 6-7frequencyMHz U16LE;8device ready;9low-power-disarm;
 10-11pit frequencyU16LE;12table available;13band count;14channel count;
 15power-level count. Earlier/unsupported replies need explicit partial state.
Frequency/band/channel/power are FC settings, not measured RF output. Device
ready and reported PIT are distinct from configured frequency and must remain
visible. Never label the FC's reported setting as an independently measured
transmit frequency or power.

Read137 MSP_VTXTABLE_BAND: one-byte1-based band index. Reply: echoed indexU8,
name lengthU8, name bytes, band letterU8, factory/custom flagU8, channel countU8,
then channel frequenciesU16LE. Validate all lengths and count bounds. A zero
frequency is unavailable, not selectable. Original Toolbox parser source14
really consumes the factory flag; the recovered source dropped this field.

Read138 MSP_VTXTABLE_POWERLEVEL: one-byte1-based power index. Reply: echoed
indexU8, power valueU16LE, label lengthU8, label bytes. Preserve the FC label and
index; the raw value is device dependent and is not universally milliwatts.
Read tables once per identity/table generation; refresh status on demand or a
bounded page interval. Original Toolbox repeats88 on Dashboard/VTX only when
VTX is enabled through FC MSP and interval>0 (default10s; installed TEST VTX off).

UI delivery: connected/offline/reading/error states; reported channel vs pending
selection; actual FC band/channel grid; power labels; PIT/LPD/device-ready state;
favourites linked to actual available frequencies. Keep local favourites when
o FC is connected, clearly local. Incomplete tables must not look complete.

Acceptance: compare88/137/138 with Betaflight Configurator on the same FC; handle
custom bands, duplicate frequencies, zero/unavailable channels, power labels,
missing/unsupported VTX, device-not-ready, truncated/late tables and reconnect.
Read88/137/138 can register an MSP VTX client in firmware; they do not write FC
configuration but are not devoid of protocol side effects. Keep normal gates.

3. VTX APPLY / PIT / PERSISTENCE — follows validated reads; separate transaction
Original VTXMSP bytecode source28-29 read branch only sets UI capability from
mspReady AND channel-table-ready. Source33-64 executes writes only for explicit
fn=='send'; decompiled Lua falsely appears to fall through into sending.
Original send queues89(write) ->250(write/save) ->88(readback). The panel uses a
long ENTER action and requires telemetry plus setable; global MSP gating stops
wire traffic when armed. This is real Toolbox functionality currently absent.

Original89 payload is four bytes: frequency-or-encoded-channelU16LE, powerIndexU8,
PIT U8(0/1). With a ready table and band/channel arguments it encodes
(band-1)*8+(channel-1); otherwise it sends MHz. Official modern API also accepts
longer extensions for lowPowerDisarm, pitFrequency, explicit band/channel/freq
and table modification. Those extensions are not necessary for initial parity
and must not be emitted with guessed/default values that overwrite other fields.

AERODECK proposal: stage a desired channel/power/PIT separately from reported
state; allow Apply only after current disarmed FM, matched Betaflight identity,
fresh88 and complete validated relevant tables. Preserve every unrelated field.
Send only the intended typed89 transaction; verify88 after acknowledgment. A
write acknowledgment proves acceptance, not the RF hardware achieved a setting.
Expose distinct pending/accepted/readback-confirmed/mismatch/timeout states.
Save250(empty body) is a separate persistence step; firmware rejects250 while
armed. Read back again after save. Do not silently apply on tile highlight.

Retries: an unanswered89/250 may already have executed. Resolve with readback
before repeating; do not copy five blind EEPROM retries. Reconnect invalidates
pending apply. Explicit PIT false must remain distinct from nil/no change;
reference bytecode uses truthiness fallback in this parameter path, which is a
reason to specify correct false handling rather than blindly copy expressions.

Acceptance: physical supported VTX, disarmed, prop-free bench; compare FC readback
and actual receiver/channel behavior; PIT on AND off; changes lost without save
vs persisted after power cycle; rejected/timeout/mismatch path; armed/link-loss
cancel. Unsupported VTX hardware remains unavailable rather than fake controls.
This audit introduces no commands and performs no RF/FC writes.

4. GPS FIX / DILUTION / SATELLITES / HOME — concrete improvements over reference
Current app's split screen is structurally useful but only has basic CRSF
sensors. Satellite count alone cannot prove fix type. Toolbox's original
TBS/GPS source49 sets POS_FIX = Sats > configured threshold; source50 derives
GPS_HDOP = clamp(Sats-4,0,9) when inferred fix is true. That internal quality
value is not measured HDOP. Its source61-65 home coordinates are app-local and
freeze after inferred fix plus ARMED, not read from the FC's home registers.
Do not reproduce an inferred 3D-fix badge or call the derived value real HDOP.

Read106 MSP_RAW_GPS, empty request: fix flagU8, satellitesU8, latitudeI32LE(E7),
longitudeI32LE(E7), altitudeU16LE(m), ground speedU16LE(cm/s), courseU16LE(0.1deg).
API>=1.44 source adds positional DOP U16LE(/100); use actual reply length/API
checks. Label PDOP, not HDOP. The fix field is a boolean, not a 2D/3D fix-type
enum. No basic106 field provides measured HDOP or precise fix classification.
Read107 MSP_COMP_GPS: distance-to-FC-homeU16LE(m), bearingU16LE(deg), updateU8.
It does not return FC-home latitude/longitude or prove that home was initialized.
Keep LOCAL HOME vs FC HOME source labels and do not replace one silently.

Read164 MSP_GPSSVINFO: countU8 +count records of four bytes: channel/GNSS ID,
satellite ID, quality/flags, CNO. Official BF semantics differ: count<=16 is
legacy channel data, count>16 is enhanced GNSS-ID data. Enhanced records use
quality bits0-2 for lock quality and bit3 for used-in-solution; sentinel255 means
unused record. GNSS IDs0GPS/1SBAS/2Galileo/3BeiDou/4IMES/5QZSS/6GLONASS are valid
only in enhanced mode. Avoid mislabelling legacy channel numbers as constellations.
Verified BF buffers are32records:129bytes including count, within current256 cap.
Validate count/record length, filter unavailable entries, never manufacture
constellation/lock data on NMEA/unsupported firmware. Original Toolbox schedules
164 every10s on its GPS page. AERODECK can fetch on entry and refresh without
letting satellite jobs delay status/attitude. All MSP metadata retains disarmed
transport gates; passive CRSF position can continue in flight independently.

32-bit Lua: retain signed rawE7 coordinates for validation, exact display and
relative deltas before float conversion. Avoid unsigned U32 sum/float32 rounding
losing low coordinate bits. Use bytewise flags as arm-status already does. UID
hex formatting likewise should operate on bytes instead of unsigned U32 math.

UI delivery: confirmed FC fix boolean/PDOP with age; constellation totals and
per-satellite CNO/used status only when actually supplied; local home source and
capture policy; optional separate FC distance/bearing. If precise fix/HDOP is
unavailable, show unavailable. Keep historical track visibly historical.
Acceptance: no fix/many sats, low sats/valid fix, enhanced32 vs legacy16 records,
empty/255 rows, missing GPS build support, stale/reconnect, signed coordinates
near0 and dateline, local vs FC home mismatch. Compare raw data with Configurator.

5. FC STATUS / SETTINGS — distinguish app connection settings from FC tuning
AERODECK already has firmware/API, raw150 and decoded arming-disable reasons.

cycle time, I2C errors, CPU load, PID/rate profile indices, reboot flag and CPU

Read4 BOARD_INFO empty: fixed8-byte prefix then length-prefixed target/board/

Toolbox CFGFC source15-18 contains MSP enable, fixedversion2, status interval
0..5s and VTX interval0..10s. Those are app connection settings, not FC PID/rate

AERODECK has enable/disable but fixed3s status and no VTX refresh. Add deliberate
interval choices only after scheduler stability; slower status can remove the
ELRS reply-bandwidth benefit. Do not promise all12 app lists are FC configurator.
Stick calibration/profile diagrams are references; they are not transmitted.
Calibration/reboot/PID/rate/motor writes are separate future scope and should
not be smuggled into the VTX command allowlist.
