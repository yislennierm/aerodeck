OPEN AND NAVIGATE
Open SYS > Tools > AERODECK. Add the AERODECK home-screen widget through EdgeTX
widget setup; Full screen opens the same app. The compact card uses its current
shared values. Returning to compact/hidden keeps the session, local home/track,
configured alarm state and timer continuity while EdgeTX schedules its callbacks.
Battery alerts run with that scheduled app session. Opening a standalone tool
disables widget refresh until the tool closes. Foreground MSP/reference playback
is suspended when the widget leaves full screen. A standalone tool closes its
session on a controlled exit.

On first widget use, cold load, chunk execution and session initialization use
separate callbacks. The app shows STARTING AERODECK and stage progress while 13
initialization phases complete, including bounded native input discovery,
compiled source plans, the FC client and arming decoder. No partial
telemetry snapshot is presented as live. A runtime input refresh is incremental
and keeps flight/home state. The final cold callback yields before live service.

Native widget LCD buffers are transient, so every scheduled refresh paints a
frame. Slow telemetry uses four bounded callbacks: the first field batch, the
remaining fields/summary, power derivation, then session/publication. Acquisition
starts target a 200 ms period. The fields are not sampled simultaneously: at
20 callbacks/s, acquisition spans about 50 ms and publication follows about
150 ms after the first batch. Displayed raw/derived/session values stay intact
until completed publication, including repeated source-setting cancellations or
expired-work restarts. Normal callbacks read pitch/roll and immediately update the
displayed attitude, including loss.
The render-rate preference targets the standalone tool only; its bitmap buffer
persists between runs. Widgets receive transient draw buffers and always paint.
Primary source contract: development/runtime-evidence/edgetx-2124-frame-contract.json. First-sample, heavy explicit actions or exceptional FC/cache
work paint an opaque progress view instead of leaving the LCD buffer blank.
Ordinary sampling continues to paint the current page.

Slow phases can wait when earlier work uses more than the reserved instruction margin.
The complete cached page still paints, with freshly read attitude. If publication
has waited 400 ms or pending work 200 ms, sampling gets a callback without the
transport dispatcher; transport resumes with fresh guards afterward. This does
not issue RF writes or promise a maximum data age. A modal's cheaper body can
advance slow work while the PFD is hidden. Pending work older than 300 ms or
using an obsolete settings/battery revision is discarded and sampled again.
The nominal 200 ms cadence and 150 ms publication delay can stretch under load;
real radio performance remains a separate acceptance check.

A widget background SESSION ERROR suspends that instance and attempts controlled
closure. Use the EdgeTX widget Update action to retry closure/restart. If native
timer restoration fails, its session and recovery metadata remain available; a
new app instance is not silently substituted over the failed one. This is not a
promise of recovery from every arbitrary module or firmware failure.

The six top sections are stable, in PAGE/touch order:

SETTINGS, OWNERSHIP AND FILES
The twelve category definitions are Model Setup, RC Link, Model Battery,
Battery Favourites, Flight Controller, Indicators/Timers, FC Mode Indicators,
VTX, VTX Favourites, GPS, User Interface and Application.
Available categories/rows depend on effective protocol/FC/provider/VTX/pack
choices. Hidden rows keep saved values. Select a row, ENTER, adjust with rotary,
ENTER to end the draft. RTN cancels the current edit snapshot, including linked
battery-threshold adjustments. Save/Revert are focusable physical controls.
Save Settings commits app preferences; Save Battery commits only battery limits
and alert policy. Dirty badges and exit recovery keep these stores separate.

Preferences now use settings-model-<hex-model-filename>.cfg and
battery-model-<hex-model-filename>.cfg, with verified ownership/checksum, atomic
save and backup recovery. Renaming the displayed model does not change ownership.
Setup > Application offers explicit Import Legacy App Settings / Import Legacy
Battery for old name-based files. Review before importing; old files are retained.
New models retain AERODECK's documented 4.2 V/visual-only battery defaults; all
limits and sound/haptic options remain configurable. Existing values are preserved.

Timer host RADIO preserves native timer settings. Choosing AERODECK explicitly
claims the selected native timer using a reserved eight-character ADxxxxxx name.
An occupied marker blocks another app/widget instance before any timer reset.
The app checks ownership before writes, start/pause/reset and controlled release.
A controlled close/reload restores the captured timer configuration, then its
original name; elapsed time is not restored. A restoration error retains the
marker and in-memory recovery information so the app can remain open and retry.

A forced script abort or model switch can leave a stale ADxxxxxx marker. The
original configuration snapshot exists only in Lua memory; clearing that name
cannot reconstruct it. Inspect the native timer, manually restore the desired
mode/start/beeps/persistence and rename it away from ADxxxxxx before explicitly
claiming it again. A manual name change revokes app ownership without restoring
over the user's new settings. Use a controlled exit whenever possible.
New Flight clears local session/home/track and optionally selected native timer
and radio sensor statistics; FC battery counters are not reset by local arithmetic.

Diagnostics includes runtime/memory, FC, sensor health, Quick Actions, opt-in
error log, About/System and Radio Battery views. Error events are bounded in RAM;
Save Log is explicit, rate-limited and verified SD persistence. In the widget,
prepare and promotion use separate opaque Saving callbacks; Saved appears only
after final verification. A failure keeps the RAM events pending, and a model
change cancels an old pending transaction before further log IO. Model Image in
User Interface displays the current model's real image on System, caches its
handle and does no image IO when Off. No activation/licence mechanism is included.
